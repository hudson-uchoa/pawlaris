# P7-5 — E2E flows

All real-phone checks are OWNER and unrun. No emulator, screenshot or inferred
result is recorded as evidence. Follow [../e2e.md](../e2e.md) in its scenario
order: 01, 04, 05, 06, then 02, 03, 07; 08–09 have the P7-4 fixture.
The Device checkbox in spec/08-tasks.md stays unchecked for the orchestrator.

For each result, append date, build SHA, phone model, Android version, theme,
Reduce Motion setting, exact sanitized command, exit code and Maestro's raw
summary. Retain failed attempts too. On the two-phone result name both models.
Write `<serial>`, `<serialA>`, `<serialB>` and `<PC-LAN-IP>` in retained commands
and output. Never retain actual serials, addresses, passwords, tokens or email
identities. Screenshots, recordings and full Maestro reports remain local in
the ignored `docs/evidence/media/P7-5/`; describe them in words here.

- [ ] OWNER — Prepare a separate empty dev database and blob directory.
  Run the existing migration and bootstrap commands from docs/e2e.md for
  two test users. Do not reset or seed everyday family data. Confirm both
  phones reach `http://<PC-LAN-IP>:8000/api/v1/health` and use that same API.
- [ ] OWNER — Install the current bundled build on both phones. Record model
  using `adb -s <serial> shell getprop ro.product.model` and Android version
  using `adb -s <serial> shell getprop ro.build.version.release`. Confirm
  permissions, Maestro's mock location provider, and airplane mode disabling
  Wi-Fi and mobile data. Set normal display/font scaling for the five cards.
- [ ] OWNER — Run 01-login on each phone with its own test credentials.
  Confirm dashboard hydration and synced-0. Save sanitized Maestro output
  under this item; keep its private report under the ignored media path.
  Use `Invoke-E2EFlow '01-login'` with the EMAIL/PASSWORD arguments from
  docs/e2e.md, once per phone in separate terminals.
- [ ] OWNER — On A, run 04-pet-and-weight against the pet-free family. Confirm
  one dog and its saved first weight on the profile. Retain Maestro's output.
  Command: `Invoke-E2EFlow '04-pet-and-weight'`.
- [ ] OWNER — Run 05-task-create-and-fork with the dog's UUID and no previous
  templates. Confirm creation, old task's empty today section, replacement
  today, no occurrence tomorrow, occurrence in two days, and return to today.
  Command: `Invoke-E2EFlow '05-task-create-and-fork' @('-e', "PET_ID=$petId")`.
- [ ] OWNER — Run 06-walk with the synthetic mock positions. Confirm live
  metrics, an accepted position marker, pause/resume, saved detail map and a
  finished history row. Allow about 70 seconds for mocked motion. Do not
  claim measured real-world GPS accuracy from synthetic coordinates.
  Command: `Invoke-E2EFlow '06-walk'`.
- [ ] OWNER — Use the documented API helpers to end earlier templates and
  prepare the normal task. Run 02-complete-and-undo. Confirm the correct
  author appears and undo removes that occurrence's attribution.
  Run the exact `Invoke-E2EFlow '02-complete-and-undo'` command in docs/e2e.md
  with the returned task UUID, today's occurrence key and A's display name.
- [ ] OWNER — Prepare the photo-required task and grant camera permission.
  Run 03-photo-proof-offline. Capture only a synthetic scene; confirm queued
  upload while offline, persistence after process restart, uploaded state
  after reconnect and disappearance of the upload label. Confirm networking
  is restored afterward, including after a failed attempt.
  Run `Invoke-E2EFlow '03-photo-proof-offline'` with the returned photo task
  UUID and today's occurrence key as shown in docs/e2e.md.
- [ ] OWNER — End earlier templates, prepare exactly five incomplete tasks
  and wait for synced-0. Run 07-offline-queue. Confirm five pending writes,
  offline restart preserving the records, five completed cards and eventual
  synced-0. Confirm airplane mode is disabled afterward.
  Command: `Invoke-E2EFlow '07-offline-queue' $queueVariables`, with the five
  exact task UUIDs and date prepared by the documented API helpers.
- [ ] OWNER — Prepare the P7-4 performance fixture and start screens. Run
  08-hero-loop on Pets and 09-dashboard-fling on Hoje using the commands in
  docs/e2e.md. Retain Maestro output; frame budgets remain P7-4 evidence.
  Commands, separately: `Invoke-E2EFlow '08-hero-loop'` and
  `Invoke-E2EFlow '09-dashboard-fling'`.
- [ ] OWNER — Create the fresh paired task; set E2E_TASK_ID,
  E2E_OCCURRENCE_KEY and E2E_COMPLETER_NAME locally. Open its detail on both
  online phones with the unchecked occurrence visible. Run
  `node scripts/e2e-two-device.mjs <serialA> <serialB>`. Require both Maestro
  flows to pass, the right author's name on B and a PASS R5.8 summary at or
  below 3000 ms. Record the elapsed upper bound and both flow summaries.
  For another run undo on A and wait for both to show incomplete first.
- [ ] OWNER — Repeat flows 01–07 and the paired check on the final release
