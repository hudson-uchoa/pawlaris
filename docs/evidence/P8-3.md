# P8-3 — Deploy script and latency

Addresses are placeholders. The box and Docker were unavailable to the
implementer; every device step is therefore `OWNER`.

- [ ] OWNER — On the box, from `/opt/pawlaris/infra`, run
  `sudo ./deploy.sh <tag>` and record the successful health check and running
  image tag.
- [ ] OWNER — From `/opt/pawlaris/infra`, run
  `sudo HEALTH_URL=http://localhost:8000/api/v1/not-found ./deploy.sh <new-tag>`;
  record that the command exits non-zero, confirm the 404 causes an automatic
  rollback, and confirm the previous version answers
  `http://localhost:8000/api/v1/health`.
- [ ] OWNER — First create a disposable family with the bootstrap CLI. Then,
  from the owner's computer, set `PAWLARIS_API_URL=https://<host>/api/v1`,
  `PAWLARIS_EMAIL=<owner-email>`, `PAWLARIS_PASSWORD=<owner-password>`, and
  `PAWLARIS_TASK_ID=<task-uuid>`; run `node scripts/latency.mjs` and record
  p50 and p95, confirming p95 is under 100 ms. Server-Timing measures the
  server, so this step may run from the owner's computer rather than the box;
  do not pass the password as a command-line argument.
- [ ] OWNER — Before H10, remove the disposable family with
  `docker compose --env-file ../.env down -v` from `/opt/pawlaris/infra`.
  This erases the box's data and is safe only before H10.
- [ ] OWNER — Create the real family on the box with the bootstrap CLI (H10).
