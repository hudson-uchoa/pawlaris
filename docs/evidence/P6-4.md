# P6-4 — Recovery and battery prompt

Every step is OWNER and requires a physical Android phone with a development
build containing P6-4. No step has run and no result is recorded. Under each
step, the owner records the date, phone model, Android version, app build,
actual observations and any sanitized command output. Keep screenshots and
recordings only in the ignored `docs/evidence/media/` directory. Describe
them in words here; never include serials, coordinates or addresses.

- [ ] OWNER — Confirm the installed build and physical phone. Run
  `adb -s <serial> shell getprop ro.product.model` and
  `adb -s <serial> shell getprop ro.build.version.release`.
  Record the model and version, with every serial replaced by `<serial>`.
  Sign in, allow precise location, and keep Pawlaris visible.
- [ ] OWNER — On an installation that has not completed the battery step,
  open the location permission ladder and complete its earlier steps.
  Confirm the battery explanation and the two help lines for the phone's
  manufacturer. Open battery settings, leave optimization enabled, then
  return. Background and foreground the app, then force-stop and reopen
  it. Confirm the battery step does not appear again. In Settings >
  Permissions, confirm the battery row reflects the actual Android setting;
  change it in system settings, return and confirm the row refreshes.
- [ ] OWNER — Start a walk for a non-archived dog. Until the walks tab's
  start control is available, use an owner-local development harness bound
  to the signed-in runtime as `app`, while the app is visible:

  ```ts
  const dog = Object.values(app.store.getState().pets).find(
    (pet) => pet.species === 'dog' && pet.archived_at === null,
  );
  if (dog === undefined) throw new Error('A non-archived dog is required');
  await app.liveWalk.tracker.start(dog.id);
  ```

  Do not commit the harness or print the returned walk or GPS fixes. Open
  the live route through the harness's router with `/walk/live`. Wait for
  several fixes, moving enough to see distance accumulate. Record only
  the displayed distance and elapsed time, with no location information.
- [ ] OWNER — In Android Studio App Inspection > Database Inspector,
  select `pawlaris.db`. Record the result of this query as the baseline:

  ```sql
  SELECT p.seq, p.t, p.acc, p.paused
  FROM walk_point AS p JOIN local_walk AS w ON p.walk_id = w.id
  ORDER BY p.seq;
  ```

  Record the count and last sequence number. Never select coordinates,
  full rows, raw routes or full outbox bodies. Detach the inspector and
  debugger before stopping the process.
- [ ] OWNER — Run `adb -s <serial> shell am force-stop app.pawlaris`.
  Reopen Pawlaris from its launcher icon. Confirm the dashboard paints
  before the recovery sheet appears. Confirm the sheet reports the stored
  start time in the family timezone and the stored distance, with Continue
  and Finish with what we have actions. Do not dismiss it yet. Reattach
  the inspector and rerun the baseline query. Confirm every baseline
  sequence and its timestamp, accuracy and pause flag is still present.
- [ ] OWNER — Choose Continue. Confirm the live screen opens, distance
  retains the stored value and new fixes append after the baseline sequence.
  Rerun the baseline query and compare its original prefix. Confirm the
  same local walk remains and no second start is queued. For a controlled
  offline run, inspect only method and path:

  ```sql
  SELECT method, path FROM outbox ORDER BY seq;
  ```

  Expect one start request for this walk. Do not record identifiers from
  other family data. Detach the inspector and debugger again.
- [ ] OWNER — Repeat force-stop and reopen. Before finishing, read only
  the last stored timestamp and the start timestamp:

  ```sql
  SELECT w.started_at, MAX(p.t) AS last_point_at
  FROM local_walk AS w LEFT JOIN walk_point AS p ON p.walk_id = w.id
  GROUP BY w.id, w.started_at;
  ```

  Choose Finish with what we have. Confirm navigation to the walk detail
  route. In an offline run, inspect the finish request without route data:

  ```sql
  SELECT json_extract(body, '$.started_at') AS started_at,
         json_extract(body, '$.ended_at') AS ended_at,
         json_extract(body, '$.paused_ms') AS paused_ms,
         json_extract(body, '$.distance_m') AS distance_m,
         json_extract(body, '$.duration_s') AS duration_s,
         json_extract(body, '$.avg_pace_s_per_km') AS pace,
         json_array_length(body, '$.route') AS route_count,
         json_array_length(body, '$.preview') AS preview_count
  FROM outbox WHERE path LIKE '/walks/%/finish' ORDER BY seq DESC LIMIT 1;
  SELECT COUNT(*) AS local_count FROM local_walk;
  SELECT COUNT(*) AS raw_point_count FROM walk_point;
  SELECT json_array_length(points) AS cached_route_count
  FROM walk_route_cache;
  ```

  Confirm `ended_at` equals the last stored timestamp,
  the finished route is cached, and `local_walk` and its raw points are
  removed. The detail screen remains a placeholder until P6-5.
- [ ] OWNER — Exercise foreground recovery without killing JavaScript:
  start another walk, background the app and use an owner-local harness to
  run `await app.liveWalk.tracker.stop()` without deleting the local row.
  Return to the app.
  Confirm the recovery sheet appears with the retained distance. Continue
  and confirm recording resumes on that same walk.
- [ ] OWNER — Exercise recovery without a fix: disable device location
  services, attempt a walk start and confirm a durable local walk with zero
  points remains. Force-stop and reopen. Confirm the recovery sheet offers
  zero distance. Finish and inspect only the finish request's timestamp,
  metrics and array lengths with the same SQL query. Confirm start and end
  timestamps are equal,
  paused time, distance and duration are zero, pace is null, and route and
  preview lengths are zero. Restore device location services afterward.
- [ ] OWNER — Repeat the recovery sheet in light and dark themes and with
  Android Reduce Motion enabled. Check text at 130% font scale, readable
  buttons and no clipping. Confirm reduced motion uses the sheet's fade,
  and motion stops when the app backgrounds. Save any optional captures
  only under `docs/evidence/media/P6-4-<step>.png` or `.mp4`; leave every
  unobserved checkbox unchecked.
