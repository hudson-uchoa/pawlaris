# P0-10 — Local release build

Task: P0-10. Run on 2026-10-04 on Windows, using the Motorola Edge 70
(Android 17, API 37, arm64-v8a), connected through wireless debugging.
Serials and LAN addresses are redacted. No emulator is used.

## Clean release build and standalone launch

Observed on 2026-10-04 after the second clean prebuild. The generated
`android/build.gradle` contains the plugin's Windows-only staging setting.
The exact requested Gradle command succeeded:

```text
> Task :app:assembleRelease
BUILD SUCCESSFUL in 4m 24s
758 actionable tasks: 726 executed, 32 up-to-date
```

APK: `android/app/build/outputs/apk/release/app-release.apk`,
40,114,837 bytes (40.11 MB, 38.26 MiB). Inspecting the ZIP's `lib/` entries
found only `arm64-v8a`. A local copy is retained at the ignored
`.cache/P0-10/app-release.apk` because restoring the dev client regenerates
the native project.

## Development-client restoration

The first restoration prebuild stopped with `EBUSY` on the generated
`app/build/intermediates/dex/release/mergeDexRelease/classes.dex`. The
interrupted clean had already removed `gradlew.bat`. Located the cached
Gradle 9.3.1 launcher below the user profile's `.gradle/wrapper/dists` and
ran `gradle.bat --stop`:

```text
Stopping Daemon(s)
1 Daemon stopped
```

Repeated `npx expo prebuild --platform android --clean --no-install` with
`EXPO_PUBLIC_API_URL=http://<PC-LAN-IP>:8000/api/v1`; it completed. The
build guide now stops Gradle after the release build and documents this
file-lock recovery.

Observed on 2026-10-04:

```text
npx expo run:android --device motorola_edge_70 --no-bundler
BUILD SUCCESSFUL in 4m 23s
455 actionable tasks: 198 executed, 225 from cache, 32 up-to-date
Installing .../android/app/build/outputs/apk/debug/app-debug.apk
```

The installed package flags now contain `DEBUGGABLE`. Expo's automatic
launch used the LAN Metro URL and showed a connection error. The CLI also
reported a reverse-port warning for the Samsung's wireless device name;
it did not prevent installation on the Motorola. Set up the Motorola's
reverse connection manually, force-stopped the app, then cold-launched
the explicit localhost development deep link from `docs/build.md`:

```text
adb -s <serial> reverse tcp:8081 tcp:8081
adb -s <serial> shell am force-stop app.pawlaris
adb -s <serial> shell am start -W -a android.intent.action.VIEW -d 'exp+pawlaris://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' app.pawlaris
Status: ok
LaunchState: COLD
Activity: app.pawlaris/.MainActivity
TotalTime: 1075
WaitTime: 1077
Complete

GET http://127.0.0.1:8081/status
packager-status:running
Android Bundled 25913ms apps/mobile/index.ts (1404 modules)
```

Captured and inspected [the restored dev route](P0-10-motorola-dev-restored.png).
It shows Pawlaris and the development-menu button. The transient error
capture was replaced by this successful capture and is not included in
the repository. The Motorola remains on the dev client; Metro is running
with localhost forwarding. No device step remains OWNER. The task's Device
checkbox is left for the orchestrator.
