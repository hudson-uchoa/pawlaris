# P4-4 — Login and redeem device checklist

Task: P4-4. Procedure from `spec/08-tasks.md` and
`spec/07-test-harness.md` §13. **Every step is OWNER. None has been run or
given a result in this file.** Leave the task's Device checkbox unchanged.

Use the real Motorola Edge 70 and Samsung Galaxy S23 Ultra (`SM-S918B`)
listed in [devices.md](../devices.md), in both light and dark themes.
Follow [build.md](../build.md) for the local Android toolchain and USB
connection. These checks use a development client on the P4-4 tree.

When running a step, append its date, device model, Android version and
raw output or screenshot reference beneath it. Identify phones by model.
Keep serials, LAN addresses, account emails and passwords out of committed
evidence. Substitute `<serial>` and `<PC-LAN-IP>` locally only. Start each
new PowerShell terminal at the repository root unless a step changes its
directory. Run commands separately and stop on a non-zero exit.

## Start the API on the development machine

- [ ] OWNER — Confirm H1–H4 and the prerequisites in `build.md`: native
  PostgreSQL 16 is running, the database is migrated, the git-ignored
  `services/api/.env` is configured, and both phones have authorized USB
  debugging. Prepare a signed-out development-client installation on each
  phone and a working account in an empty development family. Keep the
  credentials local; do not print the environment file.

  ```powershell
  node scripts/doctor.mjs
  adb devices -l
  ```

- [ ] OWNER — Start the API in a repository-root terminal and keep it
  running. The phones and PC must share the trusted home network.

  ```powershell
  uv run --directory services/api uvicorn app.main:app --host 0.0.0.0 --port 8000 --reload
  ```

- [ ] OWNER — In another terminal, check the API health. Follow the
  Private-network TCP 8000 firewall setup in `build.md` if needed. On each
  phone, open `http://<PC-LAN-IP>:8000/api/v1/health` in the browser and
  look for `status: ok` and `db: true`. Record redacted output.

  ```powershell
  Invoke-RestMethod http://127.0.0.1:8000/api/v1/health
  ```

## Build and launch the development client

- [ ] OWNER — Build and install on the Motorola Edge 70. The dependencies
  are already installed. Set the API URL before building and before
  starting Metro.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  npx expo run:android --device motorola_edge_70 --no-bundler
  ```

- [ ] OWNER — In a second terminal, build and install on the Samsung
  Galaxy S23 Ultra.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  npx expo run:android --device SM_S918B --no-bundler
  ```

- [ ] OWNER — Start Metro over USB and keep this terminal running.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  $env:NODE_OPTIONS = '--dns-result-order=ipv4first'
  npx expo start --dev-client --localhost
  ```

- [ ] OWNER — In a repository-root terminal, run these commands for each
  phone. Record the model, Android version and API level, with serials
  redacted. Launch the signed-out app in light theme; the login form must
  paint over the Starfield without waiting for a network response.

  ```powershell
  adb -s <serial> shell getprop ro.product.model
  adb -s <serial> shell getprop ro.build.version.release
  adb -s <serial> shell getprop ro.build.version.sdk
  adb -s <serial> reverse tcp:8081 tcp:8081
  adb -s <serial> shell cmd uimode night no
  adb -s <serial> shell am force-stop app.pawlaris
  adb -s <serial> shell am start -a android.intent.action.VIEW -d 'exp+pawlaris://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' app.pawlaris
  ```

## Auth flow — repeat on both phones

- [ ] OWNER — Before entering credentials, inspect login in light theme.
  Check the paw-star mark, name, readable field labels and full-screen
  Starfield. Check `powered-by`: the Insurge signature is centered 24 dp
  above the bottom inset, has the geometry and colors of `06` §4.12, and
  is not pressable. Tapping it must not navigate or open a link. Focus a
  field: the keyboard covers the signature rather than pushing it into
  the form. Dismiss the keyboard.

- [ ] OWNER — Switch to dark theme and repeat the login and signature
  checks before entering credentials. Confirm that the form and signature
  remain legible over the themed sky.

  ```powershell
  adb -s <serial> shell cmd uimode night yes
  ```

- [ ] OWNER — Tap `login-to-redeem` to open `(auth)/redeem`. Check the
  code, name, email and password fields and `redeem-submit` over the
  Starfield. Type a lowercase sample code without submitting: it must
  become uppercase and stop at 10 characters. Check that the login-only
  Insurge signature is absent. Use Android Back to return to login.
  Repeat this navigation in light theme using `cmd uimode night no`.

- [ ] OWNER — Enter the development account credentials locally and tap
  `login-submit` while the API is running. The form stays visible with
  inline button progress. On success, the four tabs appear. Initial
  replica loading may show skeletons; after the first pull, visit the
  today, pets, walks and settings tabs and check the current empty shell
  states. Keep this family empty for the screenshots.
