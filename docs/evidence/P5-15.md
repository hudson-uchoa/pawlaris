# P5-15 — The socket at its specified path

Procedure from `spec/08-tasks.md` P5-15 and
`spec/07-test-harness.md` §13. Every device step below is OWNER and remains
unobserved. The host check found no authorized adb devices. Leave the
task's Device checkbox unchanged.

Use a real Android phone with the current development client. Follow
[build.md](../build.md#api-on-the-lan) for the development API and client
setup. Keep addresses, device serials, tokens and credentials local.
Under each executed step, record the date, device model, Android version,
tested commit, sanitized raw output or observations, and PASS or FAIL.

- [ ] OWNER — Start the development API from this tree using the API on
  the LAN procedure in `build.md`. Keep its terminal visible. Configure
  the phone's API base with the `/api/v1` suffix, install the matching
  development client, and connect the phone to the trusted development
  network.
- [ ] OWNER — Open the app, sign in to the development family, and open
  the dashboard. Observe the API terminal during this connection. Confirm
  the WebSocket handshake is accepted at `/api/v1/ws` and there is no 403
  response for the socket. Record only sanitized log lines; remove any
  addresses or identifiers before adding evidence here.
- [ ] OWNER — Confirm the phone's sync indicator shows connected after
  the socket opens. Record the visible state and PASS or FAIL. A passing
  host test alone does not establish this device result.
- [ ] OWNER — Repeat the socket and indicator observations during the
  [P5-3 two-phone check](P5-3.md). Confirm both phones connect to the
  development API without socket 403 responses before checking that a
  completion reaches the other phone.

Keep screenshots and recordings in the ignored `docs/evidence/media/`
directory. Describe their observations here; do not commit the media.
