# P7-4 — Performance gates

All phone steps below are OWNER. None has run in the implementer's sandbox.
No phone result, frame count, latency or APK measurement is recorded here.
Do not create `docs/evidence/perf-<date>.md` until a real phone run occurs.
Then record each raw result, date, phone model, Android version, build SHA,
theme, motion setting and measurement method there. Keep failures visible.
Leave the Device checkbox in the backlog unchanged for the orchestrator.

Run each command separately in PowerShell 5.1. Start at the repository root
unless a step changes directory. Substitute values locally; retained commands
and output must use `<serial>` and `<PC-LAN-IP>`, never actual serials or LAN
addresses. Captures, traces and Maestro reports stay only under the ignored
`docs/evidence/media/`; describe what they show in words in the results file.
The CLI prints summaries to stdout and never writes a dated evidence file.

- [ ] OWNER — Prepare the LAN API using `docs/build.md`, with an expendable
  test family and two members. Do not seed the family's everyday records.
  On both phones, verify `http://<PC-LAN-IP>:8000/api/v1/health` responds.
  Use the same test family on both phones so phone-to-phone latency can be
  observed. Keep the date fixed during a set of measurements.
- [ ] OWNER — Make a release APK with the seed compiled in. From
  `apps/mobile`, run these separately:

    ```powershell
    $env:EXPO_PUBLIC_PERF_SEED = '1'
    $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
    pnpm exec expo prebuild --platform android
    Set-Location android
    .\gradlew.bat assembleRelease -PreactNativeArchitectures=arm64-v8a
    Set-Location ..\..\..
    ```

  The final command returns to the repository root. Follow the release
  signing procedure in `docs/build.md`. Retain the build SHA and confirm
  `android:debuggable` is false with the SDK's `apkanalyzer manifest
  debuggable apps/mobile/android/app/build/outputs/apk/release/app-release.apk`.
  Install it on each phone with
  `adb -s <serial> install -r apps/mobile/android/app/build/outputs/apk/release/app-release.apk`.
  Stop Metro; the installed release must run without it.
- [ ] OWNER — Identify each device by model with
  `adb -s <serial> shell getprop ro.product.model` and Android version with
  `adb -s <serial> shell getprop ro.build.version.release`. Record only
  model and version. On both phones, enable system animations and turn
  Reduce Motion off. Avoid battery saver and thermal throttling.
- [ ] OWNER — Log in, wait for the test family replica to hydrate, then open
  Ajustes → Diagnóstico. Press **Preparar 90 tarefas de teste** once on one
  phone. This atomically enqueues one test pet and 90 unassigned, all-day,
  once-only task templates for today in the family timezone. Wait until both
  phones show synchronized. Repeat taps on that phone/day add no records.
  On the other phone do not seed again: sync has brought the same records.
  Use a fresh test family for another date or after completing seed tasks.
  Check Hoje on both phones has exactly 90 incomplete occurrences in scope;
  do not complete any before the fling/memory measurements.
- [ ] OWNER — Cold startup, on each phone in both themes, from the root:
  `node scripts/perf.mjs startup --serial <serial>`.
  Retain all five samples and their median. Each launch is force-stopped;
  START and the dashboard's first ready-layout marker come from epoch
  logcat. Require median **< 1500 ms**. A missing marker is a failure.
- [ ] OWNER — Warm startup, on each phone in both themes, five runs. Open
  Hoje on today's date first; press Home without force-stopping the app.
  Record the original `show_touches` setting with
  `adb -s <serial> shell settings get system show_touches`, then enable it
  with `adb -s <serial> shell settings put system show_touches 1` so the
  launcher press has a visible timestamp. Capture the launcher
  and the return to the retained dashboard using
  `adb -s <serial> shell screenrecord --time-limit 15 /sdcard/P7-4-warm.mp4`.
  During capture, tap the launcher icon, then the day-next control as soon
  as Hoje appears to demonstrate responsiveness. Pull each capture with
  `adb -s <serial> pull /sdcard/P7-4-warm.mp4 docs/evidence/media/` and rename
  locally by model/theme/run. Read the video's frame timestamps from the
  launcher press to the dashboard's visible ready frame; record frame rate,
  timing uncertainty, five samples and median. Require median **< 500 ms**;
  a sample whose uncertainty crosses the budget needs a finer real-device
  capture. Q-63 records this manual warm-start method: the once-per-launch
  marker does not fire on an existing activity's return.
  Return to today's date before the next run and restore `show_touches`
  to its original value after the last capture.
- [ ] OWNER — Hero frames, on each phone in both themes. Navigate to the
  Pets grid; have the seeded pet card visible. Put
  `C:\Tools\maestro\bin` on the local Path. Run
  `node scripts/perf.mjs frames apps/mobile/.maestro/08-hero-loop.yaml --serial <serial>`.
  The flow opens the first visible pet and returns ten times, without a new
  launch. Require **≤ 5%** janky frames and **p99 ≤ 34 ms**. Retain the
  summary and the output of
  `adb -s <serial> shell dumpsys gfxinfo app.pawlaris`.
  The CLI passes `--test-output-dir` and `--debug-output` under
  `docs/evidence/media/P7-4/` so failure screenshots and reports stay local
  ([Maestro CLI reference](https://docs.maestro.dev/maestro-cli/maestro-cli-commands-and-options)).
- [ ] OWNER — Dashboard frames, on each phone in both themes. Navigate to
  Hoje, today, at the top of the 90-card list; verify the sky is active.
  Run
  `node scripts/perf.mjs frames apps/mobile/.maestro/09-dashboard-fling.yaml --serial <serial>`.
  Require **≤ 5%** janky frames; retain the p99 as context and the raw
  gfxinfo dump. The flow uses ten pairs of fast swipes and selects only
  test ids. Do not substitute a smaller dataset or disable the starfield.
- [ ] OWNER — Idle memory, on each phone in both themes:
  `node scripts/perf.mjs memory --serial <serial>`.
  The command opens Hoje and waits 30 seconds. Do not touch the phone.
  Require **total PSS ≤ 300 MB**; retain the summary and raw
  `adb -s <serial> shell dumpsys meminfo app.pawlaris` output.
- [ ] OWNER — Release artifacts, using the same release environment:
  `node scripts/perf.mjs bundle`, then
  `node scripts/perf.mjs apk --apk apps/mobile/android/app/build/outputs/apk/release/app-release.apk`.
  Require **Hermes bytecode ≤ 6 MB** and **arm64-v8a-only APK ≤ 60 MB**.
  The bundle command exports using the pinned Expo CLI, reads Android's
  metadata entry and validates the Hermes header (even if Expo names it
  `.js`). The APK command inspects ZIP entries to reject other ABIs.
  Sizes use 1 MB = 1024 × 1024 bytes; exact bytes are printed too.
- [ ] OWNER — Same-interaction feedback, on each phone in both themes and
  with Reduce Motion both off and on. After the frame/memory runs, disconnect
  Wi-Fi/mobile data and complete a task. Observe press-in feedback followed
  by a lit checkbox on release, with no network wait. Reopen the app offline
  and confirm the record survived. Component tests cover the press/release
  behavior; document the observed release behavior separately.
- [ ] OWNER — Phone-to-phone latency, on Wi-Fi and the LAN API. Reconnect,
  synchronize both phones, then complete a different occurrence on phone A
  while phone B has it visible. Capture both screens in one external video
  stored under `docs/evidence/media/`. Measure from A's release to B's lit
  checkbox and correct attribution; require **≤ 3 s**. Repeat in the other
  direction. Record samples, model roles and network conditions.
- [ ] OWNER — Idle JS, on each phone in both themes. Capture a 30-second
  Android Studio System Trace from the installed release (enable Android's
  shell profiling if required), with Hoje untouched and sky active. Save
  traces only under `docs/evidence/media/`. Inspect the Hermes JS thread:
  no recurring per-frame JavaScript; the minute-aligned data tick and
  socket heartbeat are distinct from animation. Navigate away and background
  the app and observe that ambient animation work stops. Record observations
  and trace method; an unavailable JS trace leaves this check pending.
- [ ] OWNER — Build an ordinary release with `EXPO_PUBLIC_PERF_SEED`
  removed, install it, and confirm Diagnostics has no seed action. Restore
