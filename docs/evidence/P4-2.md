# P4-2 — Cosmos kit device checklist

Task: P4-2. Procedure from `spec/08-tasks.md` and
`spec/07-test-harness.md` §13. **Every step is OWNER. None has been run or
given a result in this file.** Leave the task's Device checkbox unchanged.

Use the real Motorola Edge 70 and Samsung Galaxy S23 Ultra (`SM-S918B`)
listed in [devices.md](../devices.md), in both light and dark themes.
Follow [build.md](../build.md) for the local Android toolchain and USB
connection. These captures use a rebuilt development client; they do not
assert release-build performance budgets.

When running a step, append its date, device model, Android version and
raw output or recording reference beneath it. Identify phones by model;
keep serials and LAN addresses out of committed evidence. Substitute
`<serial>` and `<PC-LAN-IP>` locally only. Start each new PowerShell
terminal at the repository root unless a step changes its directory.
Run commands separately and stop on a non-zero exit.

## Rebuild the development client first

Skia is a new native module. Reusing the previous client or reloading
JavaScript alone is insufficient; regenerate and rebuild before recording.

- [ ] OWNER — Confirm H3/H4, the build prerequisites, unlocked phones and
  authorized debugging. Check the toolchain and select each phone by model.
  Record redacted output. Turn Android's Remove animations setting off for
  the four motion recordings below.

  ```powershell
  node scripts/doctor.mjs
  adb devices -l
  ```

- [ ] OWNER — From the repository root, regenerate the native project and
  rebuild/install on the Motorola Edge 70. The dependencies are already
  installed; `--no-install` preserves them. Record the build/install output.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  npx expo prebuild --platform android --clean --no-install
  npx expo run:android --device motorola_edge_70 --no-bundler
  ```

- [ ] OWNER — In a second terminal, install the rebuilt client on the
  Samsung Galaxy S23 Ultra. Record the build/install output.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  npx expo run:android --device SM_S918B --no-bundler
  ```

- [ ] OWNER — Start Metro with the same API URL, using the USB transport
  from `build.md`. Keep this terminal running throughout the captures.

  ```powershell
  Set-Location apps/mobile
  $env:EXPO_PUBLIC_API_URL = 'http://<PC-LAN-IP>:8000/api/v1'
  $env:NODE_OPTIONS = '--dns-result-order=ipv4first'
  npx expo start --dev-client --localhost
  ```

- [ ] OWNER — In a repository-root terminal, run the following for each
  phone, substituting that phone's serial locally. Record the model,
  Android version and API level under the corresponding capture. Set up
  Metro forwarding on both phones.

  ```powershell
  adb -s <serial> shell getprop ro.product.model
  adb -s <serial> shell getprop ro.build.version.release
  adb -s <serial> shell getprop ro.build.version.sdk
  adb -s <serial> reverse tcp:8081 tcp:8081
  ```

## Recording flow — OWNER, repeated for each capture

Each recording starts with the scratch route at the top, counter `0/10`
and the checkbox hollow. Look for the sky gradient, nebula and twinkle.
Scroll forward and back: the canvas stays behind the content, with the
near stars moving upward most during forward scrolling. Return to the top.

Check the single checkbox and wait at least two seconds before unchecking:
look for the star ignition, six sparks, the three joined constellation
nodes, five meteors, and the sky brightening and settling. The star stays
lit and the line remains until unchecked. In light theme the lit star has
its outline; dark has none. Uncheck and wait until the ring is hollow,
then check again. Repeat until the counter reaches `10/10`; leave the last
star lit and wait at least two seconds for its meteors to finish.

Stop screen recording with Ctrl+C in its terminal. The **next command** is
the frame-stat capture, before pulling the video or changing the app/theme.
Keep the full raw `gfxinfo` output, including its frame counts, janky-frame
percentage and percentile lines; do not replace it with a claimed result.

## Motorola Edge 70 — light

- [ ] OWNER — Select the Motorola serial, set light theme, restart the
  rebuilt client and wait for the scratch screen at `0/10` without a native
  module error. Record date, model, Android version, theme and build mode.

  ```powershell
  adb -s <serial> shell cmd uimode night no
  adb -s <serial> shell am force-stop app.pawlaris
  adb -s <serial> shell am start -a android.intent.action.VIEW -d 'exp+pawlaris://expo-development-client/?url=http%3A%2F%2F127.0.0.1%3A8081' app.pawlaris
  ```

- [ ] OWNER — Reset frame stats, start recording, and perform the complete
  recording flow above, including all ten ignitions.

  ```powershell
  adb -s <serial> shell dumpsys gfxinfo app.pawlaris reset
  adb -s <serial> shell screenrecord /sdcard/P4-2-motorola-light.mp4
  ```

- [ ] OWNER — After Ctrl+C, capture frame stats immediately, then pull the
  recording. Append raw-output and video references beneath this item.

  ```powershell
  adb -s <serial> shell dumpsys gfxinfo app.pawlaris | Out-File -Encoding utf8 docs/evidence/P4-2-motorola-light-gfxinfo.txt
  adb -s <serial> pull /sdcard/P4-2-motorola-light.mp4 docs/evidence/P4-2-motorola-light.mp4
  ```
