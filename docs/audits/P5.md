### Search procedure

The searches were driven from Python's subprocess API so each tracked
filename was a separate argument. The equivalent PowerShell invocation is:

```powershell
$tracked = @(git ls-files) | Where-Object { $_ -ne 'services/api/.env' }
rg -n --pcre2 -e $pattern -- @tracked
```

The following patterns were used, with contextual follow-up searches for
field names, URL hosts, media references and placeholders. Binary results
were investigated through file signatures, image display, PNG chunks and
printable/UTF-16 font metadata, rather than interpreting compressed bytes
as text. Broad matches such as package versions were retained for review.

| Category | Search |
|---|---|
| Coordinates | `(?<![\w.])-?\d{1,3}\.\d{4,}(?!\w)`; also `lat`, `lon`, `latitude`, `longitude`, `route`, `preview`, and their test builders |
| Private IPv4 | `\b(?:192\.168|10\.\d{1,3}|172\.(?:1[6-9]|2\d|3[01]))\.\d{1,3}\.\d{1,3}\b` |
| Other IPv4 | `\b(?:\d{1,3}\.){3}\d{1,3}\b`; URL and percent-encoded development-link context |
| Email | Full local-part/domain expression below; secondary conventional local-part/TLD search; binary metadata follow-up |
| Telephone | `(?<!\w)(?:\+\d{1,3}[ .-]?)?(?:\(?\d{2,3}\)?[ .-]?)?\d{4,5}[ .-]\d{4}(?!\w)` and `\b\d{10,15}\b` |
| Street/contact context | Case-insensitive `street`, `avenue`, `address`, `rua`, `avenida`, `postal`, `postcode`, `zipcode`, `cep` |
| Device identity | `serial`, `imei`, `android_id`, `ssid`, `bssid`, `mac.address`, `adb`, wireless debugging names and `transport_id`; colon-separated MAC pattern `\b(?:[0-9A-Fa-f]{2}:){5}[0-9A-Fa-f]{2}\b` |
| IPv6 | `\b(?:fd[0-9a-f]{2}|fe80):[0-9a-f:]+`, case-insensitive; loopback context |
| Opaque strings | `\b[0-9a-fA-F]{32,}\b` and `(?<![\w/+])[A-Za-z0-9/+_-]{40,}={0,2}(?![\w/+])` |
| Credentials | `BEGIN (?:RSA |EC |OPENSSH |DSA )?PRIVATE KEY`, provider prefixes `gh[pousr]_`, `github_pat_`, `sk-`, `AKIA`, `AIza`, `xox[baprs]-`, plus assignments involving `password`, `passwd`, `secret`, `token`, `api.?key`, `private.?key`, `authorization` |
| Media | Case-insensitive extensions `png`, `jpg`, `jpeg`, `webp`, `gif`, `heic`, `heif`, `bmp`, `tif`, `tiff`, `avif`, `mp4`, `mov`, `webm`, `mkv`, `avi`, `3gp`, plus SVG and embedded `data:image/` / `data:video/` references |

The exact primary email expression, as a Python raw string, was:

```python
r"[a-zA-Z0-9.!#$%&\x27*+/=?^_`{|}~-]+@[a-zA-Z0-9-]+(?:\.[a-zA-Z0-9-]+)+"
```

All file sizes and binary headers were checked independently of extension.
Magic checks included PNG, JPEG, GIF, RIFF/WebP/AVI, ISO `ftyp` containers
(MP4/MOV/HEIC/AVIF), EBML/WebM/MKV, BMP and TIFF, plus the font headers.
There are nine binary files: seven PNGs and two TrueType fonts. No disguised
capture, recording, archive, database dump or file over 1 MiB was found.

## Validation and handoff

The required content gate passed, exit 0:

```text
pnpm --config.verify-deps-before-run=false verify --only content
  1 pass   0 fail   0 pending   of 1
```

The local pnpm launcher initially started a preliminary supply-chain
verification instead of reaching the repository script. Those invocations
were cancelled. The command above disables pnpm's automatic dependency
reinstallation check for this invocation only, so it can run the existing
local content gate without package installation or registry verification.
It changes neither repository configuration nor the gate's checks.
Running `node scripts/verify.mjs --only content` directly also passed with
the same one-pass summary.

The gate checks tracked files only. The new, untracked audit was therefore
also checked directly with the guard's exported `contentProblems` function.
The orchestrator's C1 disposition requires no current-tree fix. This
revision changes only the audit and its commit message; it makes no
application or dependency change.

The full `pnpm verify --allow-pending` is intentionally not run: its API
and contract commands load local settings or connect to PostgreSQL, which
conflicts with this audit's explicit no-`.env`/no-server instruction. The
task's required gate is `pnpm verify --only content`.
