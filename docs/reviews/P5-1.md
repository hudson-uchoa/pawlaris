## R1 — minor — one pet after Remédio is not tested to save together     FIXED

**Where:** `apps/mobile/src/features/tasks/TaskFormScreen.tsx:79`
**Spec:** `09` §5.1, Modo: "hidden when one pet is selected (stored as
`together`)"
**Problem:** choosing **Remédio** sets the mode to `per_pet`, even when
one pet is already selected. Only the `fields` override on line 79
turns that back into `together` on save. The mutant that drops the
override survives: no case picks a pet first and Remédio second. A
one-pet medication would then be stored as `per_pet`, against the spec.
**Fix:** a case that selects one pet, then Remédio, saves, and asserts
`completion_mode: 'together'` and `reminder_class: 'critical'` in the
created template and the queued body.

FIXED in `5b2e7b4`.

## R2 — minor — a double tap on Salvar is not tested                     FIXED

**Where:** `apps/mobile/src/features/tasks/TaskFormScreen.tsx:100`
**Spec:** AGENTS.md §3.5 (a retried tap never applies twice), the same
rule as P4-6's weight form
**Problem:** `finished.current` is the only thing that stops a second
tap. The button stays enabled until the route closes, and `createTask`
mints a new id per call. The mutant that drops the guard survives, so a
quick double tap would create two tasks with nothing to catch it.
**Fix:** a case that presses `task-save` twice on a valid new task and
asserts one `createTask` call and one queued `POST /tasks`. Add the
same for an edit (`patchTask` once).

FIXED in `9d5009c`.
