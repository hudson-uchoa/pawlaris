## R1 — minor — The swatches are labelled with token names       OPEN
**Where:** `apps/mobile/src/features/pets/PetFormScreen.tsx:149`
**Spec:** `09` §4.2 (Cor no app), `AGENTS.md` §5 (copy lives in
`strings.ts`)
**Problem:** each swatch's `accessibilityLabel` is `entry.name`, the
palette token (`polaris`, `nebula`…). TalkBack reads an English
identifier, and the label is copy outside `strings.ts`. `09` §4.2 gave
no Portuguese names; `b297339` adds them.
**Fix:** name the eight bodies in `strings.ts` as `09` §4.2 now lists
them, label each swatch from there, and assert the labels in palette
order in a pet form test.

## R2 — minor — Outra… after a list choice keeps the key          OPEN
**Where:** `apps/mobile/src/features/pets/PetListPicker.tsx:69`
**Spec:** `09` §4.2 (Outra… turns the field into free text); the Tests
line ("Outra… stores the text")
**Problem:** choosing a breed and then **Outra…** clears the value
before the text field appears. Removing `if (!freeText) onChange('')`
survives every test: the field would then show the raw key
(`maine_coon`) as text to edit.
**Fix:** a picker test that picks a list entry, then **Outra…**, and
asserts the field is empty and that typed text is what is saved.

## R3 — minor — Two avatars' chosen colour is untested            OPEN
**Where:** `apps/mobile/src/features/dashboard/PetAvatar.tsx:10`,
`apps/mobile/src/features/tasks/TaskFormScreen.tsx:155`
**Spec:** `08` P5-12 Build ("the pet's identity from `identity_color`
wherever it is drawn")
**Problem:** dropping `identityColor` from the dashboard avatar or the
task form's pet chips survives every test. Only the card, the profile
and the form preview pin it.
**Fix:** one test per screen that renders a pet with a chosen
`identity_color` different from its derived one and asserts the
placeholder's colour.

## R4 — minor — The replica backfill is untested                  OPEN
**Where:** `apps/mobile/src/db/migrations.ts:84`   **Spec:** Q-55
**Problem:** replacing the backfill's `WHERE` with `WHERE 0` survives
every test. The app behaves the same today only because `Avatar` and
`Orbit` default an absent prop to null. A pet row without the field
breaks the shared `Pet` type the rest of the app relies on.
**Fix:** a migration test that writes a pet row without
`identity_color` at the previous schema version, migrates, and asserts
the field is present and null. A row that already has a key keeps it.
