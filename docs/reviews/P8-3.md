## R1 — major — the running image is not what `.env` records   FIXED in 7389b89
**Where:** infra/deploy.sh:38, infra/docker-compose.yml:29
**Spec:** 05 §4.5
**Problem:** the tag reaches compose only through `PAWLARIS_IMAGE` in
the script's own environment. Any later `docker compose up -d`, as the
README teaches, silently moves the box to `:stable` while `.env` says
another version.
**Fix:** make `image:` in compose
`ghcr.io/hudson-uchoa/pawlaris-api:${APP_VERSION:-stable}`, delete
`PAWLARIS_IMAGE`, and let `deploy.sh` change only `APP_VERSION` and call
compose with `--env-file ../.env`. One place holds the version.

## R2 — major — the checklist cannot prove the rollback or the latency   FIXED in d403230
**Where:** docs/evidence/P8-3.md
**Spec:** 08 P8-3, 07 §13, 05 §4.5
**Problem:**
- `sudo` drops `HEALTH_URL` from the environment by default. The deploy
  then polls the real health URL, succeeds, and nothing rolled back.
- The box has no Node, so `node scripts/latency.mjs` cannot run there.

computer: `Server-Timing` is server-side time, so the path does not
matter. Create a disposable family with `bootstrap` first, then remove
it with `docker compose --env-file ../.env down -v` before H10, saying
this erases the box's data and is only safe before H10.

## R3 — major — the measurement is not the one R5.9 defines   FIXED in 5c3e546
**Where:** scripts/latency.mjs:58, :75, :85
**Spec:** 07 §9, R5.9
**Problem:**
- The login goes into the samples; R5.9 exempts it.
- `/sync?since=0&limit=1` reads from the start, so it is not incremental.
- The occurrence key is a literal date in the code.
**Fix:** take no sample from the login. Walk `/sync` to its head without
sampling, then measure the 200 calls with `since` at that revision.
Build the all-day key from `source.now()`. The tests must assert the
request sequence, that a slow login does not move the percentile, the
`since` value and the key.
