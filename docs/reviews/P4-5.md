## R1 — minor — clearing an optional field is untested                 FIXED

**Where:** `apps/mobile/src/features/pets/PetFormScreen.tsx:80`
**Spec:** `02` §2.1 R2.1 (optional fields are nullable); `04` pet bodies
**Problem:** the form turns an empty breed, colour, microchip or notes
into `null`. No case clears one, so sending `""` instead survives
(`empty breed sent as empty string`). The server would then store empty
strings where the schema means "not given".
**Fix:** in the edit case, clear one optional field. Assert that the
PATCH body carries `null` for it and that the replica row holds `null`.

FIXED in `39b02c7`.

## R2 — minor — a double tap on Salvar is untested                      FIXED

**Where:** `apps/mobile/src/features/pets/PetFormScreen.tsx:79`
**Spec:** `AGENTS.md` §3.5; `09` §4.2
**Problem:** `finished` stops a second **Salvar** before the route has
closed. Each `createPet` call generates its own id, so without the
guard two quick taps on a new pet would enqueue two pets. The guard
works, but removing it survives (`double save`).
**Fix:** press `pet-save` twice on a valid new pet. Assert one
`createPet` call, one outbox entry, one pet in the store and one
`onClose`.

FIXED in `d44f378`.

## R3 — minor — the archive sheet says "A" for every pet                FIXED

**Where:** `apps/mobile/src/i18n/strings.ts:39`
**Spec:** `09` §4.2, as clarified in `c64d9e7`
**Problem:** the spec gave the copy only as the example "A Aurora sai…",
and `archiveBody` keeps that "A" for every pet. A male pet would read
"A Thor sai das tarefas…". `09` §4.2 now says the article follows
`sex`: "A" for `female`, "O" for `male`, and none for `unknown`.
**Fix:** `archiveBody(name, sex)` per `09` §4.2, with a case for each
sex in the archive sheet test.

FIXED in `2de0093`.

## R4 — blocker — the app config cannot load                          FIXED

*Found after acceptance, on 2026-10-19, while installing P4-9's
packages.*

**Where:** `apps/mobile/app.config.ts:2` (from `4077496`)
**Spec:** `05` §1 (the Expo config plugins); `AGENTS.md` §3.13
**Problem:** the config imports `./src/i18n/strings` for the permission
texts. Expo's config loader transpiles `app.config.ts` alone and cannot
resolve a TypeScript module from it, so every command that reads the
config fails with "Cannot find module './src/i18n/strings'":
`expo install`, `expo start`, `expo run:android` and prebuild. No gate
reads the config, so the verify stayed green. The app cannot be built.
**Fix:** move the two permission texts into a plain JSON file under
`src/i18n/` (for example `permissions.json`), so Portuguese stays where
rule 13 puts it. `app.config.ts` requires the JSON, and `strings.ts`
imports it for the camera screen's own copy. Prove it with
`npx expo config --type public` from `apps/mobile`, which must print the
config. The orchestrator adds a harness gate that loads the config, so
this cannot come back silently.

FIXED in `a5f5724`; the `config:mobile` gate (`f6f9a58`, `fc78389`) now
fails a config that cannot load.
