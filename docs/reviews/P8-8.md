## R1 — major — `stop` leaves the API running   FIXED in 1e123d1
**Where:** scripts/reserve.ps1 (`Stop-ReserveApi`, and the `catch` of
`Start-Reserve`)
**Spec:** 05 §4.7 (`stop` stops the API), 08 P8-8
**Problem:** the PID file holds `uv.exe`, and `Stop-Process` kills only
that process. Measured on this computer: after `Stop-Process` on a
`uv run python` parent, its `python.exe` child was still alive. The
reserve API keeps port 8001 and its connections, so the next `start`
fails at `dropdb`, which refuses a database in use, or its health check
answers from the old process.
**Fix:** stop the whole tree (`taskkill /PID <pid> /T /F`, and check the
exit code) in `stop` and in the failure path of `start`. `start` stops a
reserve that is still running, through the same function, before any
database command, and `dropdb` gets `--force`.

## R2 — minor — the blob directory has a default that gets emptied   FIXED in ec0a09c
**Where:** scripts/reserve.ps1 (`$blobDirectory`)
**Spec:** 05 §4.7 (its own blob directory), 08 P8-8
**Problem:** without `BLOB_DIR`, `start` empties `data\reserve-blobs`
inside the repository. The directory a reserve wipes should never be a
guess.
**Fix:** refuse to start, with the other refusals and before any tool,
when the reserve env file has no `BLOB_DIR`; add that refusal to
`scripts/reserve.test.mjs`.

## R3 — minor — the setup omits what `start` needs from PostgreSQL   FIXED in cdbbdc0
**Where:** docs/reserve-server.md, step 2
**Spec:** 05 §4.7
**Problem:** `start` drops and creates `pawlaris_reserve` as the user of
the reserve's `DATABASE_URL`, so that role needs `CREATEDB`, and the
database need not exist beforehand. The step says to create both.
**Fix:** give the exact `psql` command that creates the role with
`LOGIN CREATEDB` and a password typed at a prompt, and say `start`
creates the database.

## R4 — blocker — the documented command fails before it starts            OPEN
**Where:** scripts/reserve.ps1:11
**Spec:** 05 §4.7, 08 P8-8
**Problem:** `$RepoRoot` defaults to `Split-Path -Parent $PSScriptRoot`
in the `param` block, where Windows PowerShell 5.1 leaves
`$PSScriptRoot` empty. Run as `docs/reserve-server.md` says, without
`-RepoRoot`, both `start` and `stop` stop at once: "Cannot bind argument
to parameter 'Path' because it is an empty string". The tests always
pass `-RepoRoot`, so they never see it.
**Fix:** leave `$RepoRoot` without a default and set it in the body
from `$PSScriptRoot` when it is empty. Add a test that runs the script
exactly as the doc does, without `-RepoRoot`, and reaches a refusal.
