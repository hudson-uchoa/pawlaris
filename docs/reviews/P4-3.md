## R1 — minor — the unsubscribe case cannot fail                       FIXED

**Where:** `apps/mobile/src/features/shell/__tests__/SyncToastHost.test.tsx:60-68`
**Spec:** `08` P4-3 Tests (toast host subscribed to `mutation_rejected`)
**Problem:** the case unmounts the whole tree, provider included, and then
expects no alert. With the host's cleanup removed (`return () => {};`)
the case still passes, because nothing is left to render an alert into.
Mutant `SyncToastHost: no unsubscribe` survived.
**Fix:** unmount only the host while the provider and a probe stay
mounted, or spy on `events.on`'s returned unsubscribers and assert each
is called once on unmount.

FIXED in 1da5ad1 — the provider stays mounted and only the host is
removed; both events are covered. The mutant now fails 2 cases.

## R2 — minor — replacing a toast with the same text is untested       FIXED

**Where:** `apps/mobile/src/ui/primitives/__tests__/Toast.test.tsx`
**Spec:** `06` §4.7 (a new toast replaces the shown one, with a fresh
`hold.toast`)
**Problem:** every replacement case uses two different messages, so the
inner `key={message}` hides the host's `key={notice.id}`. Removing the
host key survives (`Toast: replacement keeps old notice`). Showing the
same message twice, for example two rejected mutations, would then keep
the first toast's remaining hold instead of starting a new one.
**Fix:** add the case: show "First notice", advance 3000 ms, show "First
notice" again; the alert is still shown at 3000 + 3900 ms and gone after
3000 + `hold.toast` + the exit.

FIXED in 401f71c — the case runs with and without Reduce Motion; the
mutant now fails both.

## R3 — minor — the dashboard marker's data condition is untested       FIXED
