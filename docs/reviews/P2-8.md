## R1 — minor — an integer the column cannot hold is a 500            FIXED

FIXED in 60adc6d; generated column bounds recorded in 4b1f892.

**Where:** `services/api/app/schemas/pets.py` — `sort_order`
**Spec:** `04` §1 (Bodies), as corrected with this review
**Problem:** `POST /pets` with `sort_order` of 2 147 483 648, or below
−2 147 483 648, answers `500`: the value passes the schema and the database
refuses it. The spec gave the field no range.
**Fix:** bound it to the column, so it is `422`. Test both edges, inside and
outside.

## R2 — minor — a string containing U+0000 is a 500 on every router            FIXED

FIXED in 4b1f892.

**Where:** every request body — seen on `PATCH /me`, `PATCH /family`,
`POST /auth/redeem`, `POST /auth/login`, `POST /pets`, `POST /weights` and
`POST /health-events`
**Spec:** `04` §1 (Bodies), as corrected with this review
**Problem:** PostgreSQL cannot store the character U+0000 in text, so any
string field carrying it ends in `500`. Two of those routes are public: a
caller with no account can produce the error at will. Nothing is lost or
leaked, but it is an unhandled error on untrusted input. The spec never
mentioned it; it predates this task.
**Fix:** refuse it with `422` in one place that every request body passes
through, not field by field, and move the bodies of the earlier routers onto
it. Test: one route of each router, and the two public ones.
