The location task is defined at module scope in `walks/task.ts`, and
`index.ts` imports it before the router. Each batch of fixes goes to
`walk_point` before anything else. A fix that arrives while the walk is
paused is stored flagged.

`tracker.start(petId)` works in this order:

1. in one transaction, it refuses a second walk, creates `local_walk`
   and enqueues `startWalk`;
2. it starts `startLocationUpdatesAsync` with high accuracy, a 3000 ms
   interval, no distance filter, and the "Passeio em andamento"
   service notification.

When the start fails for lack of background permission, it follows
`09` §8.1:

- it sets `kv.needs_background_location`;
- if the background grant arrives, it retries the service;
- otherwise it records the walk in mode `foreground` and watches
  positions through the same disk-first path.

`pause()` writes one paused point at the last known position.
`resume()` adds the paused time, and `stop()` stops the native
recorders. `pointStore` appends with a per-walk sequence, aggregates
only after the write, and rebuilds the shared accumulator from disk.

## R1 — minor — Only the background error takes the fallback, untested   OPEN
**Where:** `apps/mobile/src/walks/tracker.ts:58-59`
**Spec:** `09` §8.1 ("if it throws for lack of background permission")
**Problem:** the code rethrows any other start error, but no test pins
it. Sending every error down the fallback survives every test. A phone
with location turned off would then silently record in `foreground`
mode with no fixes.
**Fix:** a tracker test where `startLocationUpdatesAsync` rejects with
another error. `start` rejects, `kv.needs_background_location` stays
unset, and `watchPositionAsync` is never called.

## R2 — minor — The entry file's import of the task is untested          OPEN
**Where:** `apps/mobile/index.ts:1`
**Spec:** `05` §3 (entry file); P6-2 Build ("imported by `index.ts`")
**Problem:** Android can start the JS runtime for a location batch with
no React tree. The task must be defined by the entry file, before the
router. Removing the import survives every test, and the service would
then deliver batches to an undefined task.
**Fix:** a test that loading the entry file defines
`pawlaris.walk-location` with expo-task-manager before the router
entry loads. Mock the router entry and assert the order of the calls.
