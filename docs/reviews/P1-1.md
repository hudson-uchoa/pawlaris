**Verified by the reviewer on 2026-10-04.** `slotInstant` checks the time
itself and builds the instant from numbers; `Date.parse` is gone from
`time.ts`, and `utcDate` is exported from `dates.ts` and used for both the

**Where:** `packages/shared/src/time.ts:47`
**Spec:** `03` §4.3 (the `time` rule, added with this review); RC-3
**Problem:** the wall time is read with ``Date.parse(`${date}T${time}:00Z`)``.
`24:00` is accepted and silently becomes midnight of the next day
(`slotInstant('2026-10-03', '24:00', 'America/Sao_Paulo')` gives
`2026-10-04T03:00:00Z`), although `07` §4.1 lists `24:00` as invalid. Every
other malformed time fails only because V8's parser returns `NaN` and `Intl`
then throws. What a date parser does with a string outside the ISO format is
left to each engine, and this code also runs on Hermes.
**Fix:** check `time` against a strict `HH:mm` (hours 00–23, minutes 00–59)
and throw `RangeError` otherwise. Build `g` from the numbers with the same
year-safe UTC arithmetic `dates.ts` already has, shared rather than repeated
in `time.ts`. Tests, as now listed on the task: `24:00`, `8:00`, `08:60` and
`08:00:30` throw `RangeError`. The golden vectors must still pass unchanged.
