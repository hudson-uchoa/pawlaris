## R1 — minor — The sheet coming back after a dismiss is untested       OPEN
**Where:** `apps/mobile/src/features/walks/WalkRecoverySheet.tsx:33`
**Spec:** `02` R4.6 ("Nothing is discarded silently"); `09` §8.3
**Problem:** dismissing the sheet hides the current offer, and the next
foreground offers it again. No test pins the second offer. Changing the
condition so that one dismiss hides the sheet for good survives every
test. The unfinished walk would then stay on the phone with no way back
until the app restarts.
**Fix:** a test that dismisses the sheet, triggers a foreground, and
asserts that the sheet is offered again for the same walk.

## R2 — minor — Where Continuar and Encerrar lead is untested            OPEN
**Where:** `apps/mobile/app/_layout.tsx:113`, `:117`
**Spec:** `09` §8.3; `09` §6.2 (Encerrar → `walk/[id]`)
**Problem:** after **Continuar** the app opens `walk/live`, and after
**Encerrar com o que temos** it opens `walk/[id]`. Neither is pinned:
removing the navigation after **Continuar** survives every test. The
member would then be left on the dashboard with a walk recording and no
live screen.
**Fix:** a runtime-route test, like P6-3's `liveRoute` tests, that
presses each action and asserts the route it lands on.

## R3 — minor — Recovery before the first paint is untested              OPEN
**Where:** `apps/mobile/src/bootstrap.ts:225`
**Spec:** `06` §1.3 rule 1 ("An `await` before first paint is a
defect"); `09` §8.3 ("at startup")
**Problem:** the recovery check returns until the first paint, so the
dashboard paints before the sheet. Dropping `!painted` survives every
test: a foreground event during launch would then read the database and
raise the sheet before the first paint.
**Fix:** a runtime test where a foreground event arrives before
`afterFirstPaint()`. It asserts no recovery check and no sheet, and that
both come after the first paint.
