## R1 — major — a login is stored before anyone can ask whose it is   FIXED

**Where:** `apps/mobile/src/auth/session.ts`, `authenticate`
**Spec:** `10` §8.1, Login — rewritten with this review
**Problem:** `login` and `redeem` put the new tokens in the secret store
and overwrite `kv.session_user` as soon as the server answers. The rule for
a login by a different person — confirm, wipe, then pull — needs the
previous user still on record, and needs nothing of the new session on the
phone until the wipe has run: a process killed in between would otherwise
start with one person's tokens over another's replica and outbox. The spec
did not say so; the code took the obvious reading.
**Fix:** as `10` §8.1 now reads. `login` and `redeem` ask the server and
answer with the session, storing nothing. A new `adopt(session)` stores it:
the active server's tokens in the secret store, `kv.session_user`, that
server's `signed_out` cleared. `refresh` goes on storing what it receives.
Tests: `login` and `redeem` write no token and no `kv.session_user`, and
leave `signed_out` as it was; `adopt` writes all three; the existing cases
that sign in adopt what `login` returned.

FIXED in 33cfc3c. `login` and `redeem` return the server's answer and write
nothing; `adopt` writes the tokens of its server, `kv.session_user`, and
clears that server's flag; `refresh` adopts what it receives. Eight new
cases. The tests that signed in through `login` now adopt what it returned;
their expected values are the same.

## R2 — minor — an answer outside the table throws                    FIXED

**Where:** `apps/mobile/src/api/errors.ts`, `classify`
**Spec:** `10` §4.1 — the last row, added with this review
**Problem:** a status that is neither 2xx, 4xx nor 5xx makes `classify`
throw. It will be called inside the drain loop, where a throw is not a
class: the entry stays at the head and the queue stops behind it. The
implementer listed this as an assumption, which is how it was found.
**Fix:** `permanent` for anything the table does not name; `classify`
never throws. One test with a `302` and one with a `101`.

FIXED in ae01220. The last line of `classify` answers `permanent`; a `302`
and a `101` are tested.

## R3 — minor — the wire types are reached through another package    FIXED

**Where:** `apps/mobile/src/auth/session.ts`, line 1
**Spec:** `08` P2-6 — the wire types are hand-written in `entities.ts` and
