## R1 — minor — redeem takes any text as an email            FIXED

FIXED in 9ebe014.

**Where:** `services/api/app/schemas/auth.py` — `Redeem.email`
**Spec:** `04` §3 (`/auth/redeem`), as corrected with this review
**Problem:** the spec said nothing about the address, so nothing checks it.
Redeeming with `""`, `" "` or `no-at-sign` answers `200` and creates the
account. Worse, redeeming as `removed+<id>@pawlaris.invalid` with the id of
a current member also answers `200`, and from then on removing that member
fails with `500` every time: the address the removal writes is taken.
**Fix:** validate the address as `04` §3 now says, in the request schema, so
a bad one is refused before the claim. Tests: each bad shape and the reserved
domain → `422`, and the invite is still unused.

## R2 — minor — after eight users every new one gets the first key            FIXED

FIXED in 93959b6.

**Where:** `services/api/app/services/family.py:137`
**Spec:** `03` §2 (identity keys), as corrected with this review
**Problem:** "wrapping around when all eight are taken" could be read two
ways, and the code takes the first key for the ninth user and again for the
tenth and the eleventh. The bootstrap CLI cycles. The wording was the spec's.
**Fix:** the rule `03` §2 now states — the key used by the fewest users of
the family, the first in the list among equals. Test: with each key used
once, the ninth user gets the first key and the tenth the second.

## R3 — minor — the checks repeated under the lock are tested on one route            FIXED

FIXED in e3cdb52.

**Where:** `services/api/tests/api/test_family.py:167`
**Spec:** `03` §1.2 ("before any check or write"); `08` P2-7 Tests, as
extended with this review
**Problem:** every leader-only write re-reads the actor after taking the
lock, which is what stops a leader demoted or removed a moment earlier. The
race is tested for `PATCH /family/members/{id}` only. Without the re-read in
`patch_family`, `remove_member` or `create_invite`, or without its
`disabled_at` test, every test passes.
**Fix:** run the race on each of the four leader-only routes: a leader
demoted while their request waits for the lock gets `403`, one removed
meanwhile gets `401`, and neither writes anything.

## R4 — minor — seven assertions that cannot fail            FIXED

FIXED in e4702bd; concurrent identity-selection check strengthened in 4980df6.

**Where:** `services/api/tests/api/test_family.py`,
`services/api/tests/auth/test_invites.py`
**Spec:** `04` §3, §4; `08` P2-7 Tests, as extended with this review
**Problem:** each of these defects, planted in the service, passes the suite.
**Fix:** one assertion or case each.

- *Removal unassigns every template of the family.* The test assigns all of
  them to the removed member. Keep one assigned to someone else and assert it
  stays.
- *A disabled leader counts as a leader.* Add a family whose other leader is
  disabled: the enabled one cannot be demoted or removed (`409`).
- *`used_by` is written on every invite.* Keep a second, unused invite and
  assert its `used_by` stays null.
- *Redeem does not take the family lock.* Assert the lock is held when the
  key is chosen, or redeem two invites at once and assert different keys.
- *Removing a disabled member runs the removal again.* The clock is frozen,
  so nothing differs. Advance it before the second `DELETE` and assert the
  row and the family revision are unchanged.
- *Invite codes may contain `I`.* Assert every character of a created code
  is in the Crockford alphabet.
- *Bounds.* A family name of 0 and of 61 characters → `422` (today a wider
  schema would reach the database check as a `500`); a password of 7
  characters → `422`, of 8 → accepted.

## R5 — minor — redeem issues its session with a second copy of the code            FIXED

FIXED in f8b0244.

**Where:** `services/api/app/services/family.py:157-187`;
`services/api/app/services/auth.py:228` (`_issue_session`)
**Spec:** `04` §3 (session lifetimes)
**Problem:** login and refresh issue a session through one helper; redeem
writes the refresh row and builds the `Session` again by hand. The two

**Fix:** issue redeem's session through the same helper, so there is one
copy and the P2-3 tests cover it.
