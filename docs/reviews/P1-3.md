## R1 — major — carry-over must not depend on the frequency           FIXED

FIXED in `59568d9`. Carry-over now checks `ends_on` instead of frequency.
DV-19 pins every-three-days doses on off days with no end date, an end date
of today, or a future end date. DV-24 and DV-28 pin missed occurrences from
ended and forked templates. These three cases first failed on assertions
against the previous implementation, then all 28 day view cases passed.

**Where:** `packages/shared/src/dayView.ts:122`
**Spec:** `02` R6.5 and `07` §4.2 as changed with this review; ADR-033
**Problem:** the code excludes `daily` templates from the carry-over, as R6.5
said when the task was built. `daily` covers every 2, 3 or 30 days: a dose
due every 3 days that was missed disappears the next morning, while a weekly
one stays in Atrasadas. The owner decided on 2026-10-04 that one rule holds
for every frequency (ADR-033). This is a change of the spec, not a defect of
the implementation.
**Fix:** replace the frequency in the condition with the end date: a template
carries when the viewed day is today, it has no occurrence dated today, and
it has not ended (`ends_on` is null or not before today). A rule of every
day then never carries, because it always has an occurrence today; an ended
or forked template never carries, which the owner also decided — otherwise
every edit of a daily task would leave yesterday's missed occurrence in
Atrasadas beside the new version. Tests, as `07` §4.2 now states them:
DV-19 — every day, missed yesterday → not carried; every 3 days, missed on
its last date, off day today → carried, with `originalDate` set to that
date. DV-24 — the ended template missed yesterday and nothing is carried.
DV-28 — the forked template's occurrence missed the day before is not
carried.

## R2 — minor — four behaviours are implemented but not tested         FIXED

FIXED in `7d7b6ae`. DV-24 tests each exclusion independently with active
linked pets for the deleted and ended templates, and separately tests
archived and soft-deleted pets. DV-9 requires exactly one done item and
empty incomplete groups. DV-27 excludes the same completion dated yesterday.
Temporarily removing each of the four reviewed guards produced an assertion
failure in its corresponding case. All guards were restored; this finding
changes only tests.

**Where:** `packages/shared/src/dayView.test.ts` — DV-9 (`:121`), DV-24
(`:269`), DV-27 (`:300`)
**Spec:** `07` §4.2 (the cases, sharpened with this review)
**Problem:** the code is correct in each of these, but removing it leaves
every test green:

1. **A soft-deleted template.** DV-24's deleted template points at pets that
   are not in the test's pet list, so it is skipped for having no active pet
   whether or not `deleted_at` is checked.
2. **A completion from another day.** Dropping the date filter in the orphan
   loop would list every old completion of an ended template under today's
   Concluídas. No test has one.
3. **The archived pet's completion.** DV-9 checks `done[0]` only. If that
   completion surfaced as a second, orphan item, the test would not notice.
4. **A soft-deleted pet.** Only archived pets are tried.

A fifth survivor, the frequency check, is removed by R1.

**Fix:** one commit of tests, no change to `dayView.ts`: DV-24 proves each of
its three conditions alone, the deleted template with active pets, and adds a
soft-deleted pet; DV-27 adds the same completion dated the day before and
expects nothing; DV-9 expects exactly one item in `done`. Confirm each by
removing the code it guards and watching the test fail.
