## R1 — minor — two actions are pinned to a tag object, not a commit   OPEN

**Where:** `.github/workflows/ci.yml:41,74,102` (`pnpm/action-setup`), `:79`
(`astral-sh/setup-uv`); `docs/versions.md:170-171`
**Spec:** `docs/versions.md` ("immutable action pins"); GitHub's hardening
guidance asks for a full commit SHA
**Problem:** the SHA after `pnpm/action-setup@` and `astral-sh/setup-uv@` is
that of the annotated tag object `v6` / `v7`, not of the commit the tag points
to. Checked against the GitHub API: each resolves as a tag object, and the
commits API answers "No commit found" for it. The runner peels it, so the
workflow works and the pin cannot move, but it is not what the comment and
the versions table claim, and tools that audit pins do not recognise it. The
other five actions are pinned to the commit of their tag.
**Fix:** pin to the commits the tags point to —
`pnpm/action-setup@0977fd99725f1db4007ccb2928dbb4e90d06cc86` and
`astral-sh/setup-uv@37802adc94f370d6bfd71619e3f0bf239e1f3b78` — and update
`docs/versions.md`.
