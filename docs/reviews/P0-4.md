## R1 — major — a 500 leaves no trace of its cause                      FIXED

FIXED in `a674c7d`. Request failures and failed callbacks include formatted
tracebacks in ERROR JSON records under the request id. The regression tests
first failed for missing logging details, then passed; response bodies remain
generic and remaining callbacks still run.

**Where:** `services/api/app/main.py:62-66`, `services/api/app/db.py:46-56`
**Spec:** `05` §7 "No error is silent" (added with this review), pillar 1
**Problem:** `TimingMiddleware` catches every unhandled exception, answers
with the 500 problem and does not re-raise, so Starlette's and Uvicorn's own
error logging never sees it. The only line written is the `INFO` "Request
completed" with `status: 500`: no exception type, no message, no traceback.
Probed with a route raising `RuntimeError` — no log record carried it. The
same holds for a failed after-commit callback: `transactional` logs "After-
commit callback failed" and drops the exception. On the box, and in every
later task's failing test, a 500 would be undiagnosable.
**Fix:** keep the middleware answering the 500 itself (the response must
carry `Server-Timing`), and log the exception there: one `ERROR` JSON line
with the usual fields plus `exc`, the formatted traceback, under the same
`request_id`. Do the same in `transactional` for a failing callback. The
traceback never goes into the response body. Tests, as now listed on the
task's **Tests** line: in `test_errors.py`, the probe's failing commit → 500
problem+json `internal_error` and an `ERROR` line whose `exc` names the
exception; in `test_commit_order.py`, the failing callback is logged with
`exc`. No new probe route is needed.

## R2 — minor — the clock guard misses an aliased import                FIXED

FIXED in `1cda6bc`. The guard resolves datetime and time import aliases.
Seven forbidden-source samples and an allowed-clock sample prove the guard
before it scans the application. All nine guard tests pass.

**Where:** `services/api/tests/security/test_no_naive_time.py:13-15`
**Spec:** `05` §2.1 Time
**Problem:** the test only matches `datetime.now` when `datetime` is a bare
name. A file in `app/` containing `import datetime as d` and
`d.datetime.now(d.UTC)` passes both this test and Ruff `DTZ` (probed). The
spec asked for a search for `datetime.now`, which would have caught it.
`time.time()` slips through as well; `05` §2.1 now names it.
**Fix:** report any `.now` / `.utcnow` attribute whose base ends in
`datetime`, however it was imported, and any `time.time`. Have the test first
prove the guard on a sample source containing those forms, then scan `app/`.

## R3 — minor — coverage misreports lines after an awaited session call  FIXED

FIXED in `ba82f49`. Coverage traces greenlets and threads. The full API suite
passes with 37 tests, 93.64% total coverage, and 100% coverage of `app/db.py`.

**Where:** `services/api/pyproject.toml:42-43`   **Spec:** `08` P0-4 Build
**Problem:** SQLAlchemy's async session runs on greenlets, and coverage is
not told. `app/db.py` lines 36 and 41-42 — the commit and the callback loop,
which the tests plainly exercise — are reported as never run (91%). With
`concurrency = ["greenlet", "thread"]` the same run reports 100%. Left as it
is, the 85% floor will drift down for no reason as the API grows.
**Fix:** add `concurrency = ["greenlet", "thread"]` to `[tool.coverage.run]`.

## R4 — minor — the contract check hides why the exporter failed         FIXED

FIXED in `516f78a`. The contract check prints exporter stderr and spawn errors.
Controlled checks with an invalid timeout and a child process lacking uv first
failed for missing diagnostics, then passed and confirmed exit 1 in both cases.

**Where:** `scripts/contract-check.mjs:13-16`   **Spec:** `08` P0-4 Build
**Problem:** when `python -m app.export_openapi` fails, the script prints
only "OpenAPI exporter failed." and discards stderr. Seen during this review

**Fix:** print `exported.stderr` (and `exported.error`, if set) before
exiting 1.
