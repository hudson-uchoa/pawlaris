## R1 — minor — nothing tests a page of exactly `limit` rows            OPEN

**Where:** `services/api/tests/sync/test_sync.py` — SY-4 (`:104`)
**Spec:** `04` §6 ("has_more = more remained"); `08` P2-6 Tests, as extended
with this review
**Problem:** with `has_more = len(changes) >= limit` every test passes. When
exactly `limit` rows remain, that version answers `has_more: true`, and the
phone makes one more request to receive nothing. No row is lost, so the tests
that follow `has_more` to the end do not notice.
**Fix:** one test, no change to the code: with exactly `limit` rows above the
cursor, one call returns them all with `has_more` false and `revision` equal
to the family's revision; with `limit + 1`, `has_more` is true and the cursor
is the last row returned.
