## Spec corrections made with this review

The task was built exactly as written; the gap is in the spec. RC-2 listed
`Date.now`, argument-less `new Date()` and the local-time getters, but probing
the finished rule showed other ways to reach the host's clock or timezone that
it lets through: `Date()` as a function, `new Date(2026, 0, 1)` (read as
host-local time) and `toLocaleString` and its siblings. A recurrence engine
that used one of them would give different answers on the dev machine
(UTC−3), in CI (UTC) and on the phones.

- `03` §4.2 RC-2 now names those forms too.
- `08` P1-1 — the first task that writes date code — extends the rule and its
  lint fixtures before anything else. P0-3 stays accepted as built.
