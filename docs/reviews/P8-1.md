## R1 — major — PostgreSQL accepts no connection from the API            OPEN
**Where:** infra/postgresql.conf, infra/docker-compose.yml:10
**Spec:** 05 §4.2, §5
**Problem:** the compose command points `config_file` at this file, so
the image's own configuration, which sets `listen_addresses = '*'`, is
not read. The server then keeps the default, `localhost`, inside its
container. The API reaches it across the Docker network and every
connection is refused. The container's healthcheck runs inside it and
stays green, so `depends_on` does not reveal this.
**Fix:** add `listen_addresses = '*'` to `infra/postgresql.conf`, with
a comment saying the port is never published to the host.

## R2 — major — the deploy check cannot reach the API            OPEN
**Where:** infra/docker-compose.yml:44
**Spec:** 05 §4.4, §4.5
**Problem:** `05` §4.5 polls `http://localhost:8000/api/v1/health` from
the box, and `tailscale serve` needs a host port, but the API only has
`expose`. Every deploy would roll itself back.
**Fix:** publish `127.0.0.1:8000:8000` in place of `expose`. `05` §4.4
now says this. Update the sentence in `infra/README.md`.

## R3 — major — the default image does not exist            OPEN
**Where:** infra/docker-compose.yml:29, infra/README.md:27
**Spec:** 05 §4.5
**Problem:** `ghcr.io/owner/pawlaris-api:stable` is a placeholder. CI
publishes to the repository owner's namespace.
**Fix:** default to `ghcr.io/hudson-uchoa/pawlaris-api:stable`, which
is public. Remove the README's instruction to edit the image.

## R4 — minor — bootstrap creates directories nothing uses            OPEN
**Where:** infra/bootstrap.sh:7, :50
**Spec:** 08 P8-1
**Problem:** data lives in the named volumes, so `data/postgres` and
`data/blobs` stay empty and suggest a location that holds nothing.
**Fix:** remove `DATA_ROOT` and both directories. Keep the named
volumes: the image's ownership of `/data/blobs` carries into them,
which a root-owned bind mount would not.
