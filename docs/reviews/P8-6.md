## R1 — blocker — `docker volume rename` does not exist   FIXED in 56fbde1
**Where:** docs/disaster-recovery.md steps 3 and 10
**Spec:** 08 P8-6 (move the data aside), 00 P8
**Problem:** Docker has no command to rename a volume. Step 3 fails at
its first rename, after the stack is already down, and step 10, the way
back, fails the same way.
**Fix:** set each volume aside by copying it. Create a volume named
`<volume>-drill-<suffix>`, copy into it with a one-off container of an
image already on the box (the postgres image of the compose file:
`docker run --rm -v <old>:/from:ro -v <new>:/to <image> cp -a /from/. /to/`),
compare the two (file count and `du -s`), and only then `docker volume
rm` the original, so compose creates it empty. Stop if the label filter
finds anything but exactly one volume. Step 10 reverses it the same way:
copy the set-aside volumes back into fresh volumes with the original
names, after moving the failed ones aside by copying too.

## R2 — major — the copy to the box cannot run   FIXED in d27a2be
**Where:** docs/disaster-recovery.md steps 4 and 5
**Spec:** 08 P8-6, 05 §6
**Problem:** `scp` writes into `/opt/pawlaris` as the SSH user, who
cannot write there, and scp from Windows does not carry the executable
bit, so `sudo ./restore.sh` then fails. The private key lands in a
shared directory, and is not removed when the restore fails.
**Fix:** copy `infra/`, the archive and the key into a directory in the
SSH user's home; install `infra/` with `sudo cp -r` into
`/opt/pawlaris/infra` and `sudo chmod 755` its `.sh` files; `chmod 600`
the key; give `restore.sh` that path; remove the key right after
`restore.sh` whatever its result.

## R3 — minor — step 5 describes a different restore.sh   FIXED in d84eed1
**Where:** docs/disaster-recovery.md step 5
**Spec:** 05 §6
**Problem:** it says `restore.sh` creates fresh volumes and verifies the
archive. It does neither: compose creates the empty volumes because step
3 set the old ones aside, and `restore.sh` decrypts, restores, gives the
new epoch and starts the API itself.
**Fix:** describe what the script does, and say step 6's `up -d` is a
check that the stack is up.

## R4 — major — the fixed commands break in three places            OPEN
**Where:** docs/disaster-recovery.md steps 3, 5 and 10
**Spec:** 08 P8-6
**Problem:** in `compare_volume`, the line ends after `=`, so the shell
runs `test "<a>" =` alone, which fails, and the second line as a
command. In step 5, `sudo cp -r "$staging/infra" /opt/pawlaris/infra`
copies into `/opt/pawlaris/infra/infra` when that directory exists, as
it does on a box that ran the stack, and `exit "$restore_status"` closes
the owner's SSH session.
**Fix:** keep each `test` on one line, or end the first line with a
backslash; copy with `sudo cp -r "$staging/infra/." /opt/pawlaris/infra/`;
replace the `exit` with a check that prints the result and tells the
owner to stop on a non-zero status.
