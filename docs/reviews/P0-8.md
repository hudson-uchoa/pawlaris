## R1 — major — a commit written in the editor is always rejected        FIXED

**Where:** `scripts/guard-commit-msg.mjs:7`, `:33-41`
**Spec:** `08` P0-8 Build ("wired as a `commit-msg` hook"), `07` §12
**Problem:** git runs the `commit-msg` hook before it strips its own comment
lines. A message written in the editor still ends with the `# Please enter
the commit message…` block, so the guard takes that block for the last
paragraph, finds no `Task:` there and fails. Reproduced in a scratch
repository: the same message passes with `git commit -F` and fails with
`git commit -e -F` ("A phase commit requires a Task: P<n>-<n> footer."). With
`commit.verbose`, the diff after the scissors line is checked as body text
too. Plain `git commit` and `git commit --amend` are therefore unusable on a
phase branch.
**Fix:** before validating, drop everything from the scissors line
(`# ------------------------ >8 ------------------------`) to the end, then
every line starting with `#`. Tests, as now listed on the task's **Tests**
line: the `AGENTS.md` example followed by git's editor comments passes, and
so does the example followed by a scissors line and a diff with a long line.

FIXED in `f9dffaa`. The guard removes the scissors section before filtering
comment lines. Both regression tests failed before the fix and pass after
it, with LF and CRLF input. The fix commit itself passed the installed hooks
using `git commit -e -F` with `commit.verbose=true`.

## R2 — minor — the spec guard lets the implementer accept its own task  FIXED

**Where:** `scripts/guard-spec.mjs:20-25`   **Spec:** `08` P0-8 Build
**Problem:** the guard allows any state change on any checkbox line of
`08-tasks.md`, so a commit without the orchestrator role can set a task to
`[x]` or tick a `**Device:**` box. `AGENTS.md` §3 rule 2 and §4.2 step 6 give
the implementer exactly one change: its task from `[ ]` to `[~]`. The task
text said "checkbox lines", which the code follows; the text was too loose
and is corrected with this review.
**Fix:** allow only a task line (`- [ ] **P…`) going from `[ ]` to `[~]`.
Tests: `[ ]` → `[~]` passes; `[~]` → `[x]`, `[ ]` → `[x]` and any change to a
`**Device:**` box fail; the orchestrator override still passes.

FIXED in `cad5da8`. Only `[ ]` → `[~]` on a task heading passes. Acceptance,
reverse transitions, non-task checkboxes and all Device state changes are
rejected. Regression assertions failed before the fix and pass after it;
the same cases exercise the staged Git index and the orchestrator override.
