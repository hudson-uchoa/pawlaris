## R1 — major — the verification database is never dropped            OPEN
**Where:** infra/backup.sh:28
**Spec:** 05 §6
**Problem:** `dropdb` has no `-U`, so it connects as `root`, which has
no role. `|| true` hides the failure, `pawlaris_verify` stays, and
`createdb` fails on every later night: backups stop.
**Fix:** pass `-U "$db_user"`, and drop any leftover database before
`createdb`. `db_user` must be set before the trap can reach it.

## R2 — major — the blob tar cannot write to its bind mount            OPEN
**Where:** infra/backup.sh:107
**Spec:** 05 §6
**Problem:** `mktemp -d` makes a root-only directory, and the `api`
container runs as `pawlaris`. Writing `/backup/blobs.tar` is denied, so
every backup fails after verification.
**Fix:** drop the bind mount; have the container write the tar to
stdout (`tar -C /data -cf - blobs`) and redirect it to `$blobs_tar`.

## R3 — major — restore fails on a rebuilt box            OPEN
**Where:** infra/restore.sh:33
**Spec:** 05 §6, 08 P8-6
**Problem:** on a rebuilt box nothing is running, so `compose exec`
fails. That is the case this script exists for.
**Fix:** run `compose up -d --wait postgres` before the first `exec`.
Remove the unused `VERIFY_USER`.

## R4 — major — bootstrap installs the wrong files            OPEN
**Where:** infra/bootstrap.sh:47
**Spec:** 08 P8-1, P8-3, P8-4
**Problem:**
- `deploy.sh` is not installed, yet P8-3's checklist runs it from
  `/opt/pawlaris/infra`.
- `pull-backup.ps1` is installed on the box, where it cannot run.
- Run from `/opt/pawlaris/infra`, `install` fails because source and
  target are the same file, so a second run stops there.
**Fix:** add `deploy.sh`, remove the `.ps1` block, and skip the copies
when `SCRIPT_ROOT` equals `INFRA_ROOT`.

## R5 — major — the scheduled pull cannot work            OPEN
**Where:** infra/README.md:75, docs/evidence/P8-4.md:18, scripts/pull-backup.ps1:20
**Spec:** 05 §6
**Problem:** variables set in a shell never reach a Task Scheduler run.
With no terminal, an unknown host key or a passphrase prompt hangs.
**Fix:** set the three values with
`[Environment]::SetEnvironmentVariable(..., 'User')` in the README and
the checklist. Pass `-o BatchMode=yes` to every `ssh` and `scp`.

## R6 — minor — the checksum names a deleted temp path            OPEN
**Where:** infra/backup.sh:111
**Spec:** 05 §6
**Problem:** the `.sha256` records `.tmp.XXXXXX/backup.tar.age`, so
`sha256sum -c` cannot check the archive.
**Fix:** write the hash with the archive's own file name.

## R7 — minor — the truncation step proves the wrong thing            OPEN
**Where:** docs/evidence/P8-4.md:11
**Spec:** 08 P8-4
**Problem:** `| head -c 128` kills `pg_dump` with `pipefail`, so the run
fails before the verification under test. It also leaves
`last_backup.json` failed.
**Fix:** add `truncate -s 128 "$dump_file"` after the dump in the copy,
and finish with a normal `sudo ./backup.sh`.

## R8 — minor — the tests cannot catch these            OPEN
**Where:** scripts/backup-scripts.test.mjs
**Spec:** CLAUDE.md §Reviewing a task
**Problem:** the regexes match names, not behaviour, and pass with R1
and R2 present. `/before.*restored|restored.*after/s` is true of any

`--wait postgres` precedes the first `exec` in `restore.sh`.
