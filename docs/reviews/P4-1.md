## R1 — major — the walk formatters print fractional values            FIXED

**Where:** `apps/mobile/src/i18n/format.ts:40-58`   **Spec:** `09` §10
(Distance, Duration, Pace)
**Problem:** `movingSeconds` and `paceSecPerKm` in `packages/shared/src/walk.ts`
return non-integers (`(now - startedAt - pausedMs) / 1000`,
`movingS * 1000 / distanceM`), and a live distance is a sum of GPS segments.
`formatPace(855.4)` returns `14:15.399999999999977 /km`,
`formatDuration(1812.7)` returns `30:12.700000000000045`, and
`formatDistance(999.6)` returns `1.000 m` — none of them the `mm:ss` or
`1,00 km` shapes the table asks for. The tests pass only integers. `09` §10
did not say how to round (the reviewer's gap; it does now, in this review's
spec commit): distance is rounded to whole metres before the unit is chosen,
duration is whole seconds rounded down, pace is rounded to the nearest second.
**Fix:** apply those three rules in the three functions, and add the table's
three new examples as cases (`999,6` → `1,00 km`, `1812,7` → `30:12`,
`855,4` → `14:15 /km`), plus a pace that rounds up into the next minute
(`899,6` → `15:00 /km`).

FIXED in d0d23bd — the three rules are applied and the four cases are
tested; the reviewer read the diff.

## R2 — minor — the order of month days and times is never tested    FIXED

**Where:** `apps/mobile/src/i18n/__tests__/format.test.ts`   **Spec:** `09`

**Problem:** every schedule case passes month days and times already in
