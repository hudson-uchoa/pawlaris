# 08 — Implementation Backlog

Ordered. One task per session, top to bottom, on the phase's branch. How to work
a task — branch, reading, commits, when to stop — is in `AGENTS.md` §4. The
definition of done is in `07-test-harness.md` §1.1.

**Checkbox states:** `[ ]` not started · `[~]` implemented, awaiting review
(set by the implementer) · `[x]` accepted (set by the orchestrator).

**Do not reorder phases.** P1 and P2 are what every screen depends on being
correct. Building screens first is the classic way to end up rewriting them.

Every task has the same shape:

- **Depends** — tasks that must be `[x]` or `[~]` first, and owner prerequisites
- **Read** — the only spec sections needed; `03 §5` means `spec/03-data-model.md` section 5
- **Build** — what to create
- **Tests** — write these first and watch them fail
- **Gate** — commands that must each exit 0. Run every backticked command
  separately (the dev shell has no `&&`), then `pnpm verify --allow-pending`
- **Device** — a check that needs a phone or the box; tracked on its own, it
  does not block the task's acceptance or the tasks after it *(07 §13)*
- **Not here** — what is tempting and belongs to a later task

Every task that adds a dependency appends it, with its version, to
`docs/versions.md`. Every screen task uses only strings from
`apps/mobile/src/i18n/` and works in both themes.

- [ ] **P1-1 — Calendar dates and timezone functions**
  **Depends:** P0-3 · **Read:** `03` §4.3 · `07` §3, §4.1
  **Build:**
  - `src/dates.ts` — `type DateKey = string`; `isDateKey`, `parseDateKey` →
    `{y, m, d}`, `formatDateKey`, `addDays(key, n)`, `daysBetween(a, b)`,
    `weekdayOf(key)` (0 = Monday … 6 = Sunday), `mondayOf(key)`,
    `daysInMonth(y, m)`, `monthsBetween(a, b)`, `compareDateKey`. Implemented
    with `Date.UTC` arithmetic only.
  - `src/time.ts` — `localDate`, `localTime`, `slotInstant`, `startOfLocalDay`
    with the DST rules of `03` §4.3. The offset for an instant comes from
    `Intl.DateTimeFormat(..., { timeZone }).formatToParts`; formatters are cached
    per timezone. `slotInstant` algorithm, with `offset(x)` = the zone's UTC
    offset at instant `x`:
    1. `g` = the wall time read as if it were UTC
    2. `o1 = offset(g − 24 h)`; `c1 = g − o1`
    3. if `offset(c1) === o1` → return `c1` (the normal case, and the *first* of
       an ambiguous pair)
    4. `o2 = offset(c1)`; `c2 = g − o2`; if `offset(c2) === o2` → return `c2`
       (a time after a transition on the transition day)
    5. otherwise the wall time does not exist → return `c1`
